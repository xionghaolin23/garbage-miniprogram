# 页面与逻辑

| 页面 | 行为 |
| --- | --- |
| 首页 | 家庭地址、所选日期场次、截止状态、会员权益、备注、规则确认、继续原预约、所选日期任务、7 天日期切换、已预约人数和满额状态 |
| 订单 | 分页加载、状态筛选、下拉刷新、打开详情 |
| 订单详情 | 场次和地址快照、支付/取消、会员跳过、退款状态、照片查看、异常原因 |
| 我的 | 当前家庭、月卡状态、功能入口、退出登录 |
| 登录 | local 联调家庭；production 预留 wx.login 链路 |
| 家庭地址 | 小区选择、楼栋/单元/房号、放置位置；登记后只读及客服入口 |
| 小区入驻申请 | 确认提交小区、恢复未确认请求、查看本人申请和审核原因、通过后返回选地址 |
| 月卡 | 当前权益、购买服务日期、首次开通/续费、未完成购买恢复 |
| 固定计划 | 每天一次卡默认晚上，中午/晚上互斥选择；两次卡支持两场开关、放置位置、备注、保存确认 |
| 服务规则 | 收费、截止、退款、次日生效、续费、计划及隐私说明 |
| 联系客服 | 配置后拨号或复制微信，未配置显示明确说明 |

## 代码分层

- `services/api.js`：后端端点封装。
- `services/checkout.js`：创建支付单和恢复原请求。
- `services/intents.js`：按环境、用户及购买类型隔离持久化请求号。
- `services/payments.js`：本地/微信支付分支，支付结果查询，订阅触发。
- `services/summary.js`：分页获取今日服务（用于“我的”页），避免大量取消记录挤掉有效任务。
- `utils/request.js`：网络、会话头、401、错误及服务器时间校准。
- `utils/format.js`：金额、北京时间、权益日期、截止状态、订单视图。
- `components/`：订单卡片与加载/错误/空状态。

## UI 默认行为

- 不设计精确上门时间，直接展示小区配置的场次范围。
- 中午、晚上可独立勾选；选两项即对应后端两场订单，不引入 BOTH 状态。
- 家庭地址缺失先登记；小区停用隐藏新预约，保留查看已有任务。
- 没有固定计划时不替用户默认开启，需要明确选择后保存。
- 客服信息未提供前不展示虚构号码；隐私运营信息的未配置部分如实标明。
- 订单列表筛选作用于已加载页，明确显示可继续加载，避免把“未加载”误报为“没有”。

### 家庭地址楼层

新地址增加“所在楼层”正整数必填输入，不根据房号推算。已有地址缺失楼层时显示一次补填入口，确认后刷新地址；其他地址字段仍不可自行修改。地址主标题继续使用“7栋101单元101号房”，楼层单独展示。
